# Pair for two — Android

Android port of the iOS cribbage app at `~/Projects/Pair for two`. The two apps play each other
over the local network; see [PLAN.md](PLAN.md) for the design and [PROTOCOL.md](PROTOCOL.md) for the
wire format.

## Running it

### In Android Studio

Open this folder, pick the **app** run configuration and the **`pft_phone_36`** device, and press
Run. That AVD is a Pixel 7 on API 36 — the `sbn_*` AVDs belong to StarBattleAndroid and work just as
well, but this one is this project's.

The app currently drops **straight into a pass-and-play game** in feedback-scoring mode. That is
scaffolding while the menu and connect screens are built (PLAN.md §10 phase 6) — `RootScaffold` will
own that decision.

### From the command line

```bash
# Start the emulator (skip if Android Studio already has one running)
$ANDROID_HOME/emulator/emulator -avd pft_phone_36 &

# Build, install and launch
./gradlew :app:installDebug
$ANDROID_HOME/platform-tools/adb shell am start -n com.jirofeingold.pairfortwo/.MainActivity
```

`ANDROID_HOME` is whatever `sdk.dir` in `local.properties` points at.

### What you can do in it

The table is playable end to end for one hand at a time: cut for deal, discard to the crib, the
two-step starter cut, pegging, the three shows, then the next hand. Scoring works both ways — the
slider stages an amount and the **+N** button commits it, or **+1** adds a point immediately.

**The game is landscape only.** The layout is designed for it, exactly as the iOS one is.

Not there yet: the winner and loser celebrations, the scoring replay, check-my-count, and all the
chrome — menu, connect screen, settings, help, onboarding.

## Tests

```bash
./gradlew :core:test :app:testDebugUnitTest
```

Everything that matters lives in `:core`, which is pure Kotlin/JVM and needs no emulator — the
cribbage rules, the engine, the wire protocol, the LAN transport's socket layer and the view model.
A whole game plays out in a JVM test in milliseconds.

The scorer and engine are **differential-tested against the iOS implementation**: the fixtures in
`fixtures/` are generated by the Swift code itself, so agreement means the two apps genuinely count
and referee identically. See PLAN.md §3.

## Proving the two apps talk

From the **iOS** repo:

```bash
./tools/run-lan-interop.sh
```

That builds the shipping `LANTransport.swift` as a command-line process and pairs it with this
repo's `LanTransport` over real Bonjour and a real TCP socket, both directions. macOS only — it
uses `dns-sd` in place of mDNS.
